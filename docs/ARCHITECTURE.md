# Code layout

Layer-first layout under `lib/`. Each layer may import only what its row
lists in the "May import" column; anything else is a layering violation.
`tool/check_layers.dart` enforces this table (imports, exports and
`package:dataset_training_tool/` URIs alike; a `part` must stay in its own
directory), flags direct file I/O outside `services/`, and runs in CI. Change both together: `test/tool/check_layers_test.dart`
fails when they disagree.

| Directory | Holds | May import |
| --- | --- | --- |
| `main.dart` | Entry point: builds the providers and `DatasetToolkitApp` | everything |
| `views/` | Screens, panels and dialogs: app-specific UI that knows which feature it belongs to | everything below |
| `widgets/` | Reusable UI building blocks. No imports from `views/`. A widget that only one panel uses and that is written for that panel belongs next to it in `views/panels/` | `state/`, `services/`, `models/`, `theme/`, `utils/`, `l10n/`, `app_info.dart` |
| `state/` | `ChangeNotifier`s exposed through Provider (`AppState`, `DatasetState`, …) and controllers that drive them (`TagOps`, `DataTransfer`) | `agent/`, `services/`, `models/`, `theme/`, `utils/`, `l10n/`, `app_info.dart` |
| `agent/` | The LLM agent runtime (`AgentSession`) and its tools. The tools act on app state, so this folder and `state/` import each other by design | `state/`, `services/`, `models/`, `utils/`, `l10n/`, `app_info.dart` |
| `services/` | I/O and external systems: dataset files (`DatasetStore`: images and the caption files beside them), JSON import/export dialogs, settings storage, HTTP APIs, LLM clients (`services/llm/`), fonts, dictionaries, launching the browser. No imports from `state/`. A service may be a `ChangeNotifier` to report loading progress; `AppState` owns it and views listen with `ListenableBuilder` | `models/`, `theme/`, `utils/`, `app_info.dart` |
| `models/` | Plain data types and their pure logic. No Flutter widgets, no state | other `models/` |
| `theme/`, `utils/` | Design tokens and theme; small pure helpers (no I/O) | other files in their own folder, and `models/` |
| `l10n/` | `.arb` sources; `app_localizations*.dart` is generated by `flutter gen-l10n`, never edited | none |
| `app_info.dart` | Version constants, kept current by the bump-version skill | none |

Inside `views/`:

- `workbench/`: the main window shell (`WorkbenchView`, its top bar, icon rail,
  status bar, and the `ShortcutRelay` that routes its keyboard shortcuts into
  panels).
- `panels/`: the docked panels and the pieces they share (for example
  `tag_context_menu.dart`) or that only one of them uses (`subdirectory_picker.dart`).
- `dialogs/`: every modal opened via a public `show…Dialog` function. A small
  dialog that one panel opens and nothing else needs can stay private in that
  panel's file. `views/settings_view.dart` (`showSettingsDialog`) predates this
  rule and has not been moved yet; new dialogs go in `dialogs/`.
- `image_preview_window.dart`: the root widget of the separate preview window,
  which `main.dart` runs in its own engine.

## Conventions

- Files are `snake_case.dart` and named after their main public class or
  concept, one per file. Private helper widgets stay in the file that uses
  them, and so do top-level helpers nothing else calls (make them `_private`).
  `widgets/panel_widgets.dart` is the exception: it is the kit of small shared
  panel pieces (buttons, search field, glass surfaces, …).
- Only `services/` reads or writes files. Other layers hold `File` objects as
  paths and call a service (the one exception is the UI decoding images with
  `Image.file`/`FileImage`): dataset images and captions go through the
  `DatasetStore` that `DatasetState.store` exposes. `tool/check_layers.dart`
  flags direct calls such as `.readAsString(` or `.exists(` by method name.
- Inside `lib/`, import with relative paths (`prefer_relative_imports`).
  Tests import `lib/` with `package:dataset_training_tool/...`; `test/tool/`
  imports the script it tests relatively, since `tool/` has no package URI.
- `test/` mirrors `lib/`: a test for `lib/state/tag_ops.dart` lives at
  `test/state/tag_ops_test.dart`. A test named after a class sits with that
  class; an end-to-end feature test named after a model (`caption_json_test`,
  `prompt_preset_test`) sits with that model in `test/models/`, even though it
  also drives `state/` and `views/`.
  `test/widget_test.dart` is the app smoke test; `test/tool/` tests `tool/`.
- Before pushing, run the same checks CI runs (after `flutter pub get`, so the
  formatter sees the package's language version):

  ```bash
  flutter pub get
  flutter gen-l10n && git diff --exit-code lib/l10n
  dart format --output=none --set-exit-if-changed lib test tool
  flutter analyze
  dart run tool/check_layers.dart
  flutter test
  ```

Lint rules live in `analysis_options.yaml`, on top of `flutter_lints`.
